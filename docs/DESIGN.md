# 女朋友专属点菜小程序 · 设计方案 v1

> 状态：**需求定稿，待开工**。所有决策来自 grilling 访谈 Q1–Q44。
>
> **修订记录**：v1.0 → v1.1 —— 点菜交互由「点一下即选中、一键提交」改为「**购物车 + 底部浮条 + 半屏列表**」（用户修正：购物车能让她看清自己点了什么，再决定删还是加，仪式感更强）。连带调整：订单模型去掉份量、新增本地购物车模型（§3.4）、首页与提交成功页结构、验收标准。

---

## 0. 一句话定位

一个**双人自用**的微信小程序：她点菜 → 企业微信群响一声（你俩都知道今晚吃什么）→ 你俩一起做 → 做菜时能照着菜谱一步步走 → 做过的菜留下做法和复盘笔记。

**它不是外卖系统**：没有价格、没有支付、没有库存、没有配送。

## 2. 功能清单

### M1 · 点菜闭环（第一个可交付版本）

**她（点菜端）**
1. 打开小程序 → 直接看到今晚的菜单（无需登录注册、无需授权手机号）
2. 按分类浏览：家常菜 / 汤 / 主食 / 甜点（分类可在 config 里改）
3. 「她爱吃 ♥」的菜自动置顶
4. 每道菜卡片：成品图、菜名、一句话简介、口味标签（辣/清淡/耗时）
5. 点一下菜 = **加入购物车**（卡片上出现选中态），再点一次 = 移出
6. **底部浮条**：「已选 3 道菜 ▸ 就吃这些」，点一下从底部**铺开半屏购物车列表**
7. 在购物车里可以：**删除某道菜**、收起列表继续加菜、一屏看清"今晚的菜单"全貌
8. 可给整单写一句备注（可选）：「少放辣」「想喝汤」
9. **购物车本地暂存**：中途退出再打开还在（12 小时内有效），提交成功后清空
10. 提交 → 庆祝动画 + 专属文案 + 今晚菜单清单
11. 菜品详情页：简介 + **菜谱精简版**（配料表 + 步骤文字，不含你的复盘笔记）+ 加入购物车按钮
12. 历史订单页：看以前点过什么，**一键「再来一次」**（把历史订单重新灌进购物车，可改后再提交）

**你（管理端）**
13. 连点页面标题 5 次 → 解锁管理入口（她看不到）
14. 新增/编辑菜品：菜名、分类、简介、成品图（拍照上传）、标签、`她爱吃` 开关、上架/下架
15. **菜谱编辑**：配料表（增删行）、步骤（增删、调顺序、改文字）、攻略链接、复盘笔记
16. 订单列表页：看所有订单（谁点的、什么时候、备注），手动标记删除

**系统层**
17. `login` 云函数自动识别身份（你 / 她 / 访客）
18. 下单成功后：订单落库 + 企微群机器人推送（推送失败不影响订单）
19. `initData` 一次性灌入预置菜品与菜谱

### M2 · 菜谱与做菜模式

18. 「我的菜谱」页：所有菜的菜谱一览，按分类/做过次数排序
19. **做菜模式**：
    - 一屏清单视图（所有步骤，可勾掉）
    - 一步一屏视图（大字号 + 下一步按钮 + 顶部可展开配料表）
    - 屏幕常亮（`wx.setKeepScreenOn`）
    - 步骤勾选状态存库 → 关掉再打开还在，你俩进度同步
20. **随机推荐**（Q8 的亮点）：「今天吃什么」转盘/翻牌，出结果可「就这个」或「换一个」
21. 每步配图（图片上传优化）
22. 「做过 N 次」统计，吃过/没吃过的可视化

### M3 · 锦上添花（按需）
23. 点菜攒积分 / 兑换奖励（参考 Rainbow-Cats，但需双向确认防自说自话）
24. 纪念日 / 心情打卡 / 心愿单
25. 订阅消息推送（备选通道）
26. 分享卡片：她可以把今晚的菜单分享给你

## 3. 数据模型（3 个集合 + 1 份本地购物车）

### 3.1 `config`（单文档，`_id: 'app'`）
**为什么单独一个集合**：让"你俩是谁、文案写什么、webhook 填哪"变成**能在控制台直接改的数据**，而不是写死在代码里。换微信号、改昵称、换群机器人都不用重新部署云函数。

```jsonc
{
  "_id": "app",
  "couple": {
    "herOpenid": "oXXXX（她首次打开后你从 users 里填进来）",
    "herName": "她的昵称",
    "meOpenid": "oYYYY",
    "meName": "你的昵称",
    "anniversary": "2023-05-20"          // 可选，用于文案
  },
  "ui": {
    "appTitle": "小厨房",
    "herOrderButton": "就吃这些",
    "successTitle": "今晚有口福啦 ❤",
    "successSubtitle": "他马上开火 🔥",
    "emptyMenuText": "菜单还在准备中～"
  },
  "notify": {
    "wecomWebhook": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=XXXX",
    "enabled": true,
    "atMobiles": []                       // 可选 @某人
  },
  "categories": [
    { "key": "home", "name": "家里做", "icon": "🍳", "enabled": true },
    { "key": "soup", "name": "汤",     "icon": "🥣", "enabled": true },
    { "key": "staple","name": "主食",  "icon": "🍚", "enabled": true },
    { "key": "dessert","name": "甜点", "icon": "🍮", "enabled": true },
    { "key": "takeout","name": "点外卖","icon": "🥡", "enabled": false },  // 预留
    { "key": "outing", "name": "出去吃","icon": "🚗", "enabled": false }   // 预留
  ]
}
```

### 3.2 `dishes`（菜品 + 内嵌菜谱）

```jsonc
{
  "_id": "auto",
  "name": "可乐鸡翅",
  "category": "home",                 // 关联 config.categories[].key
  "intro": "甜口的，比红烧省事",        // 她在卡片上看到的一句话
  "coverImage": "cloud://...",        // 云存储 fileID
  "tags": ["甜口", "30分钟", "新手友好"],
  "herFavorite": true,                // 「她爱吃♥」，Q11
  "avoid": ["花生"],                  // 忌口提醒（可选，显示在详情页顶部）
  "spicy": 0,                         // 0不辣 1微辣 2中辣 3重辣
  "enabled": true,                    // 上架/下架
  "cookCount": 0,                     // 做过次数，M2 统计用
  "sortOrder": 100,                   // 手动排序权重（越小越前）
  "recipe": {                         // 一道菜一个菜谱，内嵌（Q16=A）
    "ingredients": [
      { "name": "鸡中翅", "amount": "8 只" },
      { "name": "可乐",   "amount": "1 罐" },
      { "name": "姜片",   "amount": "3 片" }
    ],
    "steps": [
      {
        "order": 1,
        "text": "鸡翅两面各划两刀，冷水下锅焯一下去腥",
        "image": "",                  // M2 做每步配图时填
        "done": false,                // 做菜模式勾选状态，M2 用
        "doneAt": null
      },
      { "order": 2, "text": "..." }
    ],
    "tips": [],                       // 小贴士
    "sourceUrl": "https://...",       // 你抄的攻略链接（Q20=D）
    "sourceTitle": "下厨房 · 可乐鸡翅",
    "note": "",                       // 复盘笔记：这次火大了 / 盐少了（Q15=D 预留）
    "updatedAt": "2026-10-16T12:00:00Z"
  },
  "createdAt": "2026-10-16T12:00:00Z",
  "updatedAt": "2026-10-16T12:00:00Z"
}
```

**设计说明**
- `recipe` 内嵌：一道菜一个菜谱，不为"工艺复用"过度设计
- `done`/`doneAt` 现在就留字段，M2 做做菜模式时**不用改数据结构**
- `spicy` 用数字而非文字，方便以后做"她不能吃太辣"的过滤
- `sourceUrl` 是纯文本字段，成本近乎为零，但正好对上你"一边查攻略一边学"的真实状态

### 3.3 `orders`（订单）

```jsonc
{
  "_id": "auto",
  "openid": "oXXXX",                  // 提交人（她）
  "userRole": "girlfriend",
  "items": [
    { "dishId": "abc", "name": "可乐鸡翅", "category": "home" }   // 存快照，菜删了订单还在
  ],
  "remark": "少放辣～",                // 她的整单备注（可选）
  "mealDate": "2026-10-16",           // 用餐日（按提交时的北京时间）
  "createdAt": "2026-10-16T11:30:00Z",
  "notifyStatus": "sent",             // pending / sent / failed
  "notifyError": ""
}
```

**设计说明**
- **没有 `status` 字段**：Q29 决定不做订单状态，"做没做"不靠系统记录
- `items` 存菜名快照：即使你以后下架/删掉一道菜，历史订单依然完整可读
- `cookCount` 的增加时机：在她提交订单时对每个菜品 +1（这是"做过多少次"最诚实的信号源）

### 3.4 购物车（**本地存储，不是集合**）

**为什么放本地而不是云数据库**：购物车是"未提交的临时界面状态"，不是业务数据。如果每点一个菜都调云函数，她每选一道菜都要转圈等网络——体验灾难；而放本地则瞬时响应、离线也能选。Q24 定的"全走云函数"针对的是**菜品与订单这类业务数据**，购物车不在此列。

```jsonc
// 存在手机本地，key = 'cart'
{
  "items": [
    { "dishId": "abc", "name": "可乐鸡翅", "category": "home" }
  ],
  "remarkDraft": "少放辣～",
  "savedAt": 1760000000000     // 保存时刻的时间戳
}
```

**行为规则**
- 点菜加入 / 取消：本地数组增删，无网络请求
- 打开小程序：若 `now - savedAt > 12 小时` → 视为过期，**自动清空**（对应 Q43=C，避免"昨天想吃红烧肉，今天还在车里"）
- 提交成功 → 清空 `cart`
- 「再来一次」→ 用历史订单的 `items` **覆盖**当前购物车（然后她可以删改后再提交）
- 菜品被下架/删除后的兜底：提交时云函数会校验 `dishId` 是否仍有效，失效的菜**跳过并提示**，不让整单失败

**没有份量字段**：Q42 决定不做 ×2 / ×3。

## 4. 云函数设计（只有 2 个）

### 4.1 `login`
```
输入：无（用 cloud.getWXContext().OPENID）
输出：{ openid, role, herName, meName, config }
逻辑：
  1. 取 openid
  2. 读 config/app
  3. 匹配 openid → role = 'me' | 'her' | 'guest' | 'unbound'
  4. 若 unbound：把 openid 写进 config.couple.herOpenid（首次绑定，只绑一次）
  5. 返回角色 + 渲染文案
```
> `unbound` 的处理是**唯一的引导步骤**：你部署好后先自己打开一次（绑成 me），再让她打开一次（绑成 her）。

### 4.2 `api`（唯一业务入口）
```
输入：{ action: 'xxx', payload: {...} }
路由表：
  读（所有人都能用）
    dish.list        → 菜品列表（按分类分组、她爱吃置顶）
    dish.detail      → 单道菜详情（按角色返回精简版/全量版菜谱）
    order.mine       → 她自己的历史订单
    order.reorder    → 「再来一次」的数据准备
  写（仅她 / 仅你）
    order.create     → 校验菜品有效性 + 创建订单 + cookCount+1 + 触发通知
    dish.save        → 新增/编辑菜品（仅 me）
    dish.toggle      → 上下架 / 切换她爱吃（仅 me）
    dish.remove      → 删除菜品（仅 me）
    recipe.step.done → 勾选/取消某一步（M2，两人都可）
    recipe.note.save → 保存复盘笔记（M2）
    config.save      → 改文案 / webhook（仅 me）
内部分层：
  api/index.js      → 只做路由和身份校验
  api/actions/*.js  → 每个 action 一个文件
  api/lib/notify.js → 企微推送（独立模块，可插拔）
  api/lib/db.js     → 集合名、通用查询
```
**为什么这样做**：你在开源项目里看到的"8 个云函数逐个上传、漏一个静默失败"，用 action 路由一次性消灭。以后加功能**只改代码、重新上传同一个函数**。

### 4.3 通知模块（`api/lib/notify.js`）
```
企业微信 webhook → markdown 消息：
  🍽 今晚点菜啦！
  她：点了 3 道菜
  · 可乐鸡翅
  · 番茄炒蛋
  · 紫菜蛋花汤
  💬 备注：少放辣～
  时间：10-16 19:30
失败处理：记录 notifyStatus=failed + 错误摘要，订单照常成立（绝不让推送失败毁掉点菜）
```
