# 小厨房 · 女朋友专属点菜小程序

> 她点菜 → 你俩的企微群响一声 → 一起做 → 做菜时照着菜谱一步步来 → 做过的菜留下做法和复盘。

**这不是外卖系统**：没有价格、没有支付、没有库存、没有配送。

## 设计上的几个"刻意选择"

从开源项目里学到的教训，这个项目刻意避开了：

| 开源项目常见做法 | 本项目的做法 | 为什么 |
|---|---|---|
| 每个功能一个云函数，要上传 8 次，漏一个静默失败 | **只有 2 个云函数**，`api` 用 action 路由 | 加功能只重传同一个函数，不会漏 |
| openid 硬编码在 `app.js` 里，换人就废 | openid 存在 `config` 集合，**首次打开自动绑定** | 换微信号、交换身份都不用改代码 |
| 前端直连数据库，权限必须放开 | **前端零直连**，全走云函数，集合权限设最严格 | 拿到 AppID 也读不到你俩的菜单和订单 |
| 8 个集合、手写 JSON 数组 | **3 个集合**（菜谱内嵌在菜品里） | 录入靠管理页，不用手写 JSON |
| 文案写死在代码里 | 文案在 `config` 文档 | 改文案不用改代码、不用重传 |
| 通知和下单耦合，推送失败整单失败 | 订单**先落库再推送**，推送失败只记录状态 | 她的体验永远不受影响 |

## 数据模型（3 个集合 + 1 份本地购物车）

- **`config`**（单文档 `_id: 'app'`）：你俩的身份 openid、昵称、界面文案、企微 webhook、分类
- **`dishes`**：菜品 + **内嵌菜谱**（配料 / 步骤[含完成状态] / 小贴士 / 攻略链接 / 复盘笔记）
- **`orders`**：订单（含菜名**快照**，菜删了订单也完整）；**没有状态字段**（你俩一起做饭，不需要"接单"）
- **购物车**：存在手机本地（`utils/cart.js`），12 小时自动作废 —— 因为它是"未提交的临时选择"，放本地才能点一下就有反馈

## 日常怎么用

**她**：打开小程序 → 挑菜（点一下加入购物车）→ 点底部浮条看"今晚的菜单" → 删掉不想要的 → 写句备注 → 提交 → 看到庆祝页。
同时你的**企微群会响一声**，内容是她刚点的菜。

**你加一道新菜**：连点「我的」标题 5 次 → 「加一道新菜」→ 填菜名/分类/简介 → 加配料行、加步骤（可调顺序，也可以**把攻略整段粘贴进来自动拆步**）→ 存。
以后想做这道菜：卡片上的「做法」→「开始做菜」→ 一屏清单或一步一屏，勾掉已做完的步骤（进度会同步）。

**你改文案**：连点标题 5 次 → 「设置」→ 改文案 → 保存 → 她下拉刷新就能看到。

## 接口清单（`api` 云函数的 action）

| action | 权限 | 作用 |
|---|---|---|
| `dish.list` | 所有人 | 菜单（按分类分组、她爱吃置顶） |
| `dish.detail` | 所有人 | 单道菜（她看精简菜谱，你看全量 + 复盘笔记） |
| `order.create` | 你/她 | 提交订单 → 落库 → cookCount+1 → 微信推送 |
| `order.mine` | 你/她 | 自己点过的单 |
| `recipe.step.done` | 你/她 | 勾选/取消某一步（做菜模式） |
| `recipe.note.save` | 你/她 | 保存复盘笔记 |
| `dish.save` | 仅你 | 新增/编辑菜品与菜谱 |
| `dish.toggle` | 仅你 | 上架下架 / 标她爱吃 |
| `dish.remove` | 仅你 | 删除菜品（已点过的需 `force: true`） |
| `order.listAll` | 仅你 | 所有订单 + 通知状态 |
| `order.remove` | 仅你 | 删除订单记录 |
| `config.save` | 仅你 | 改文案/通知/分类（**不允许改身份绑定**） |
| `notify.test` | 仅你 | 测试企微推送（webhook 不下发给前端） |
| `auth.reassign` | 仅你 | 交换你俩的身份绑定（需 `{swap:true}`） |
| `initData` | 首次/仅你 | 灌入预置菜品（已有菜时跳过） |
